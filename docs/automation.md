# Автоэкспорт по изменениям памяти

Русский | [English](automation_en.md)

## Linux

После настройки плагина поиск и ручной экспорт уже доступны. Его hooks на Linux
не запускают автоэкспорт. Для событийного наблюдателя используйте постоянный
Git-клон, создайте окружение и установите только зависимость наблюдателя:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r skills/codex-shared-knowledge/requirements-watch.txt
.venv/bin/python skills/codex-shared-knowledge/scripts/shared_knowledge.py watch
```

`watch` использует нативные уведомления файловой системы. Он реагирует на
завершённую запись `MEMORY.md` и `memory_summary.md`, атомарную замену и удаление.
Событие, пришедшее во время экспорта, сохраняется для следующего прохода.
Если ручной экспорт занял блокировку, наблюдатель ждёт её освобождения ядром,
сохраняя поступающие события. Перед и после чтения снимка проверяются Linux-
метаданные открытых описателей обоих источников. Открытый писатель откладывает
сохранение до закрытия; открытый читатель не блокирует экспорт. Это также
защищает первый запуск, если запись началась до старта наблюдателя.
Другие файлы памяти, чтение файлов и простой экспорт не запускают. При старте
выполняется одна сверка для изменений, сделанных пока наблюдатель был остановлен.
`export --if-changed` сравнивает содержимое двух источников с последним манифестом
и пропускает пересборку неизменённых заметок. Поиск и ручной экспорт по-прежнему
работают без дополнительных пакетов. Вызовов модели и чтения транскриптов нет.

Для фонового запуска используйте пользовательский сервис
[examples/systemd/vaultgoblin-watch.service](../examples/systemd/vaultgoblin-watch.service).
Исправьте путь к клону и `CODEX_HOME`, если они отличаются от примера, затем:

```bash
mkdir -p ~/.config/systemd/user
cp examples/systemd/vaultgoblin-watch.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now vaultgoblin-watch.service
```

Прежний периодический таймер выключите. Не включайте одновременно экспорт на
каждый `Stop`/`SessionEnd`: конец чата не означает, что память уже записана.
В документированном списке Codex нет отдельного `MemoryUpdated`:
[официальные хуки](https://learn.chatgpt.com/docs/hooks).
Наблюдатель не требует доверия хукам Codex и не меняет `trusted_hash`.
Эта версия `watch` поддерживает Linux.

## Windows

При установке плагина запустите **Setup** или `$vaultgoblin-setup`.
Настройка сохраняет местный профиль, обновляет стабильный runtime и устанавливает
тихую задачу. Дополнительные пакеты и вызовы модели не нужны.

Плагин поставляет `SessionStart`, `Stop` и `SessionEnd` через `hooks/hooks.json`.
`SessionStart` обновляет runtime из активной установки. Команды hooks используют
`PLUGIN_ROOT`, а задача — `CODEX_HOME/vaultgoblin/runtime/`, без привязки к версии
каталога кэша. Откройте **Settings > Hooks** или `/hooks`, проверьте и разрешите
новые определения. Обновление плагина может потребовать повторной проверки доверия.

Hook быстро запускает отдельный процесс экспорта, ограниченный 240 секундами.
`SessionEnd` выполняется синхронно, поэтому не ждёт самого экспорта. Задача
`Codex Shared Knowledge Export-<profile hash>` работает при входе и каждые 5 минут:
у Codex нет документированного события записи памяти, и она может обновиться
после hooks. `export --if-changed` пропускает неизменившиеся источники; общая
блокировка предотвращает одновременную запись экспорта одного профиля.

Экспорт запускается через `pythonw.exe`; дочерний `python.exe` создаётся с
`CREATE_NO_WINDOW`. Обычный вывод, ошибки и коды завершения добавляются в
`CODEX_HOME/shared-knowledge-export.log`. Для задачи код ошибки также доступен
как `LastTaskResult`. Рядом с выбранным `python.exe` нужен `pythonw.exe`.

Имя задачи включает хеш пути `CODEX_HOME`, чтобы профили не заменяли задачи друг
друга. Старая задача `Codex Shared Knowledge Export` мигрируется только если её
`Action.Arguments` содержит точный путь текущего `CODEX_HOME` в двойных кавычках.
Чужая задача с таким именем сохраняется. Миграция плагина удаляет только прежние
обработчики с меткой VaultGoblin, сохраняя остальные hooks и правила.

Чтобы отключить автоматизацию, запустите Setup с `--no-automation`. Он выключает
hooks плагина местной настройкой и удаляет только собственную задачу текущего
профиля. Сделайте это до удаления плагина: деинсталляция сама не удаляет задачу
Windows. Настройки и знания сохраняются.
Отключение без новых `--vault` и `--device` работает и при недоступном vault:
оно не проверяет FTS5 и не требует установленного runtime экспорта.

### Без плагина

После `install` из постоянного клона выполните:

```powershell
python .\skills\codex-shared-knowledge\scripts\shared_knowledge.py install-hooks
& .\skills\codex-shared-knowledge\scripts\install_export_task.ps1 -PythonPath (Get-Command python.exe).Source
```

`install` и `install-hooks` подготавливают тот же стабильный runtime.
`install-hooks` объединяет обработчики `Stop` и `SessionEnd` с существующим
`CODEX_HOME/hooks.json` и сохраняет резервную копию прежнего файла. Разрешите
определения через штатную проверку Codex. Установщик задачи ожидает готовый runtime.
Для обновления повторите `install` с прежними `vault_path` и `device`, затем
эти две команды. Дополнительные местные поля сохраняются.

## macOS

Поиск и ручной `export` работают после Setup. Hooks плагина не запускают
автоэкспорт. Используйте ручную команду из [руководства установки](usage.md).

## Читаемая структура vault

Сначала посмотрите план. Пример для стандартного `CODEX_HOME` на Linux/macOS;
путь для Windows приведён в [руководстве установки](usage.md).

```bash
python3 ~/.codex/vaultgoblin/runtime/shared_knowledge.py organize --clean-setup
```

Для применения добавьте `--apply`. Получится:

```text
Codex Knowledge/
  README.md
  Projects/
    esensor-aqa.md
    gitms.md
    general.md
  devices/
    <device>/...
```

Проектные страницы содержат читаемые ссылки на актуальные и архивные темы.
Тексты тем, ID, имена файлов и манифесты не меняются. Наблюдатель обновляет
навигацию и при приходе экспортов другого ПК; после первого `organize --apply`
перезапустите сервис, чтобы он загрузил эту местную настройку.

`--clean-setup` удаляет только распознанные прежние установочные копии `Setup`
и старую памятку `SETUP.md`. Перед изменением они копируются в
`CODEX_HOME/backups/vaultgoblin-navigation/`, вне синхронизируемого vault.
Неизвестные ручные файлы сохраняются; ручная страница навигации не перезаписывается.
Исходники меняют в Git-клоне; установленный плагин и runtime обновляют из него.
