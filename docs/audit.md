# Независимый аудит и исправления

Русский | [English](audit_en.md)

31.10.2026. Отдельный агент без истории реализации прочитал критические пути
и воспроизвёл дефекты на временных данных. Нагрузка: один пользователь,
Windows/Linux, несколько чатов и два устройства с общим Obsidian vault.

Исходная версия проходила 57 тестов общих знаний и 250 тестов пайплайна.
Это не исключило 12 дефектов ниже. Для каждого добавлена регрессия либо
расширена соответствующая проверка. Исправления проверяются повторным прогоном.

| № | Приоритет | Воспроизводимый отказ | Исправление |
|---|---|---|---|
| 1 | P1 | `--on-conflict skip` заменял существующий файл другого источника | Writer проверяет путь назначения; merge не заменяет постороннюю заметку |
| 2 | P1 | ChangeSet менял `raw/` или `SCHEMA.md` | Запрет изменений raw/meta до staging; сохраняется проверка маршрута |
| 3 | P2 | Windows-путь делал YAML источника невалидным | Строки источников сериализуются как JSON-строки, допустимые в YAML |
| 4 | P2 | Сбой записи манифеста делал последующее архивирование невозможным | Повтор распознаёт завершённую запись архива только после восстановления прежнего SHA; изменённый текст отклоняется |
| 5 | P1 | Атомизация заменяла исходник и архивировала новый результат | Совпадение выходного пути с исходником отклоняется до записи; перед архивированием writer требует все результаты |
| 6 | P1 | `../outside.md` позволял изменить файл вне vault | Пути проверяются после `resolve`, включая прямую запись и архивацию |
| 7 | P2 | `A:B` и `A?B` становились одним файлом | Общая проверка имён до записи для документов, личных заметок и контактов; учитывается регистр |
| 8 | P2 | Второй чат обновлял SQLite между inventory и SELECT; первый падал с `KeyError` | Строка вне текущего inventory пропускается с предупреждением, чужая новая строка не удаляется |
| 9 | P2 | Новая сущность дублировала заголовок существующей | Проверяется итоговый набор сущностей с учётом обновлений |
| 10 | P2 | `renames` давал успех без переименования файлов | Неподдерживаемая операция явно отклоняется; обещание убрано из промптов |
| 11 | P2 | Неверный `wiki_folder` выводил init за пределы vault | Init, ingest, compile и lint используют общую проверку корня Wiki |
| 12 | P1 | Дедупликация переносила immutable raw в архив обычных заметок | Поиск кандидатов, merge и обновление ссылок исключают Wiki и общий слой Codex, включая настроенную папку Wiki |

Регрессии находятся в
[`test_data_boundaries.py`](../pipeline/tests/test_data_boundaries.py),
[`test_wiki_compile.py`](../pipeline/tests/test_wiki_compile.py) и
[`test_shared_knowledge.py`](../skills/codex-shared-knowledge/tests/test_shared_knowledge.py).

## Дополнительные улучшения

- Темы, исчезнувшие из нативной памяти, сохраняются как архивные с прежними ID;
  собственные проверенные резервные копии тем восстанавливаются при обновлении.
- Пути индекса переносимы между Windows и Linux; оба компонента проверяются CI
  на двух ОС. Загрузка через rclone использует Python без зависимости от Bash.
- Временные файлы создаются в папке ОС и убираются после вызова Codex.
  Диагностика проверяет выбранный CLI, не требует сразу все интеграции.
- Удалены дубли инструкций, старая установка, legacy embedding-шаблон и скрипт,
  который добавлял неподтверждённые заготовленные абзацы.
- Код, промпты, контракты и RU/EN руководства разделены по назначению.
- Новые хуки сохраняют чужие настройки, резервируют прежний файл и не читают
  текст чатов. Независимо проверены реальные вызовы на Windows с пробелами,
  кавычками и метасимволами в пути.

## Ограничения проверки

Внешние модели, NotebookLM, Google Drive и доставка файлов настоящим механизмом
синхронизации не проверялись. Linux runtime проверяется CI отдельно от локального
Windows-прогона. Не каждая вспомогательная функция интеграций прочитана целиком.
Среда не разрешила проверку junction. Прямой запуск callback не доказывает доверие
и доставку lifecycle-события самим приложением Codex; это отдельная проверка.

Для Wiki по-прежнему нужен один writer на пространство и завершённая синхронизация
перед сменой ПК. Общей транзакции всех страниц и распределённой блокировки нет.
