# Сравнение подходов

Русский | [English](comparison_en.md)

Проверено 31.10.2026 по исходникам и документации проектов. Это сравнение
возможностей и сложности внедрения, не бенчмарк скорости или качества поиска.
Конкуренты не устанавливались в рабочий vault.

| Инструмент | Основная задача | Когда подходит |
|---|---|---|
| VaultGoblin | Экспорт нативной памяти Codex по устройствам, ограниченный FTS5-поиск и отдельный пайплайн Wiki | Уже есть синхронизируемый vault; нужны предыдущие решения с небольшим расходом контекста |
| [Basic Memory](https://github.com/basicmachines-co/basic-memory) | Markdown, граф связей, MCP-инструменты, семантический и гибридный поиск | Несколько разных AI-клиентов должны создавать и редактировать общую базу через сервер |
| [QMD](https://github.com/tobi/qmd) | Локальный поиск с BM25, векторами и переранжированием моделью | Нужен поиск по большой коллекции документов по смыслу; готовы обслуживать локальные модели |
| [Obsidian Mind](https://github.com/breferrari/obsidian-mind) | Организованный vault, контекст сессии, классификация сообщений и хуки; QMD опционален | Нужен готовый рабочий процесс для нескольких агентов с принятой структурой заметок |
| [Obsidian Memory](https://github.com/kkonstvol-lab/obsidian-memory) | Wiki с источниками, отдельная оперативная память агентов и набор runtime-хуков | Нужна более широкая система ведения знаний с собственными контрактами и проверками |
| [Obsidian CLI](https://obsidian.md/help/cli) | Чтение, поиск и управление самим приложением Obsidian | Нужны действия в открытом Obsidian; CLI требует запущенного приложения |

## Вывод для VaultGoblin

Сохранить два независимых компонента и текущую синхронизацию vault. Для коротких
технических запросов с ID, именами функций и проектов лексический поиск остаётся
простым проверяемым решением. Его ограничение: запрос без общих слов с источником
может не найти нужную тему; небольшой словарь RU/EN этого полностью не решает.

Из сравнения полезны следующие практики:

- Явные границы данных: нативная память, общий экспорт, Wiki и обычные заметки
  обслуживаются раздельно. Обслуживание не должно менять источники Wiki или экспорт.
- Автоматизация с коротким обработчиком: хуки только экспортируют готовую память;
  таймер покрывает поздние изменения, а чтение контекста выбирается по задаче.
- Проверка реальных отказов: конфликты имён, прерывание манифеста, параллельный
  поиск и частичный writer проходят отдельные регрессии.
- Один источник кода и короткая установка второго устройства, без ручного
  сопровождения нескольких копий скриптов.

Эти изменения входят в текущую доработку. Итоги независимого аудита:
[дефекты и исправления](audit.md); поведение хуков: [автоматизация](automation.md).

Следующее расширение стоит выбирать по измеренным промахам на обезличенном наборе
реальных запросов. Если лексики окажется недостаточно, сначала сравнить QMD на
отдельной коллекции только общих знаний, сохранив лимиты и проверки источников.
MCP имеет смысл при появлении второго клиента, которому неудобен существующий CLI.
Сейчас эти возможности не добавлены без подтверждённой потребности.

Не проверялись сравнительная полнота выдачи, задержка на одинаковом корпусе,
потребление RAM и работа конкурентов на втором ПК. Число звёзд и заявления
проектов не использовались как доказательство надёжности.
